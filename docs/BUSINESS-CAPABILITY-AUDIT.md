# 业务能力核对：DSH 搭子

核对日期：2026-10-31。范围：当前原型、原生源码、已安装官方 SDK 0.2.1-rc.5、Nostr 官方协议、既有验收记录。本轮不更改原生实现，不向公共中继写入。

## 结论

DSH 提供插件入口、界面容器、本地受认证通信和存储；人与人的跨电脑通信由插件通过 Nostr 中继完成。无需修改官方 DSH 包，也无需以 WorkDSH 为依赖。当前适合公开聊天室加可选加密私聊，不具备完整 Slack 工作区权限体系。

## 已有能力与缺口

| 功能 | 原生现状 | 结论 |
| --- | --- | --- |
| 安装与入口 | `src/client.tsx` 注册 `sidebar.panellist` 与同名 `main` 面板；Host exact Fetch 路由、storageDomain | 使用公开 SDK，已在记录列出的宿主接入 |
| 不加好友浏览/发言 | 单大厅 kind 9；只读不要求身份，署名发言要求解锁 | 已实现 |
| 引用回复 | kind 9 + q 标签；同一消息流展示 | 已实现；原文不在当前记录时不能完整定位 |
| 多公共房间 | 原型 3 房间；原生仅单个 LOBBY_TAG | 可实现但尚未接通。房间 ID 必须贯穿事件、订阅、接收校验、队列、历史与界面状态；旧大厅标识需兼容 |
| 名片发现 | 主动开启，实验 kind 30388，租约筛选 | 已实现基础发现；限共同发现节点，不是全网用户列表。类型冲突、节点政策仍需验收 |
| 私聊 | NIP-17/44/59、kind 10050 收件配置、NIP-42 认证、邀请接受 | 已实现本插件双方流程，不等于与所有 Nostr 客户端邀请互通 |
| 断线重试 | 5 秒维护重连、持久待发队列、稳定事件 ID | 已实现本地恢复；没有指数退避。首次全部连接失败时 connect 提前返回，未创建维护定时器，需要手动重连，这是待修缺口 |
| 历史 | 公共订阅最近 30 天且 limit 200，内存最多 200 条；私聊上限 1000 | 尚无更早历史翻页和完整归档保证；中继不保证永远保留 |
| 实时刷新 | Client 3 秒轮询快照 | 能显示新消息，有至多轮询周期的额外等待；可评估公开连接事件推送能力后优化 |
| 成员/在线 | 名片租约及实际发言者可供展示 | 不具备精确房间在线名单。可先称“近期发言者”，不能将连接中继数当在线人数 |
| 搜索 | 原型有演示搜索；原生主要为名片筛选 | 聊天记录搜索尚需实现，须标明本地/已加载记录范围 |
| 屏蔽 | 本地屏蔽、基本入口限流与验签 | 可减少本机干扰，不能替全体用户禁言或撤下网络副本 |
| 私密频道、管理员踢人、准入 | 普通公共中继不实施本应用成员权限 | 当前没有。NIP-29 需要愿意托管并执行规则的专用支持中继；不能只加界面按钮 |
| 文件/图片/语音/已读 | 当前主要纯文本；中继 ACK 仅说明中继接收 | 未实现，不从外观推断具备能力 |

## 协议依据

- [NIP-C7](https://github.com/nostr-protocol/nips/blob/master/C7.md)：kind 9 文本聊天及 q 引用；房间命名空间属于本项目约定。
- [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md)：事件、单字母标签筛选；可用于约定公开房间分类，不产生访问控制。
- [NIP-17](https://github.com/nostr-protocol/nips/blob/master/17.md)：加密私信及收件中继公告。
- [NIP-42](https://github.com/nostr-protocol/nips/blob/master/42.md)：中继身份验证；认证不等于拥有任意群的成员权限。
- [NIP-29](https://github.com/nostr-protocol/nips/blob/master/29.md)：中继执行群组权限；取决于托管中继的能力与意愿。
- NIP-28 现已标记 unrecommended，不据此切换现有聊天实现。

DSH 接口依据：本地安装的官方 `@deepseek-ai/dsh-client-ui-sidebar` README “Global panel entries”、`dsh-client-ui-layout`、`dsh-client-connection`、`dsh-storage-domain` 的说明、类型及当前实现。发布页本身不作为接口存在的证据。

## 本轮验证与证据边界

- 类型检查通过。
- 使用 Desktop 自带 Node 24 运行服务测试：9/9 通过；真实回环 WebSocket，合成身份，不写公网。
- 默认终端 Node 21 低于 package.json 的 >=22.14 要求，本轮误用时网络相关用例失败；受支持运行环境下通过。不能把这组失败当作公网不可用，也不能宣称支持 Node 21。
- 既有 `.artifacts/desktop-network-verification.json`：WorkDSH Desktop 与独立官方 Web，经公共中继 7 项通过；本机同一网络。
- 既有 `.artifacts/final-build-verification.json`：6 项最终构建检查通过。历史记录不等于本轮重新测试公网。
- dataelement Desktop、不同物理设备/网络、Windows 尚未完整验证。当前预览仍是离线合成数据。

## 接入顺序

1. 补齐首次全失败自动恢复；多房间打通事件、订阅、队列和房间隔离测试，保留原大厅兼容。
2. 新 UI 接原生；成员改为近期发言者、搜索明确本地范围；更早消息按游标加载，不能悄悄截断历史。
3. 两个独立宿主验证公开浏览、发言、引用、切房不串消息、断网恢复、私聊；再做不同物理网络测试。
4. 暂不把精确在线、私密群、统一禁言、文件消息当成首版能力。

## 后续实现更新（alpha.7）

上表是实现前核对。当前已补齐默认三个房间隔离、历史分页/公开本地缓存、首次全失败后的重连、标准系统通知，以及 macOS 钥匙串自动身份。身份不再是浏览/历史/设置的门槛；整体 UI 已改成顶部导航、顶部默认房间和下方连续聊天。具体平台边界及真实记录见 NATIVE.md 最新章节；不将早期的“未实现”表格当作当前状态，也不把 macOS 结果推广到所有桌面。
