# 官方 DSH 原生接入记录

日期：2026-10-31。代码目标：`dsh-friends 0.1.0-alpha.1` / 官方 DSH `0.2.1-rc.5`。

## 环境与隔离

- macOS Apple Silicon，Node.js 24.21.0。
- 使用官方 npm CLI 与其 `web` 模板生成独立 DSH_HOME，通过官方 `dsh plugin --profile web add <tgz>` 安装。
- 测试目录独立于用户的 WorkDSH/DSH 配置，不导入真实账号、模型密钥或用户文件。
- 没有配置或调用模型，没有修改官方代码。
- 截图中的昵称、公钥和资料属于合成测试身份。

## 本轮通过

1. 官方侧栏中出现“搭子”，能打开插件自己的紧凑主面板；原生新会话等入口保留。
2. 实际创建身份、设置口令；默认网络连接和公开名片均关闭，列表中没有虚构用户。
3. 实际保存名片，并从 Host 重新读取核对。
4. 下载真实 NIP-49 加密身份备份，普通快照不包含备份密文或私钥。
5. 锁定身份、错误口令拒绝、正确口令解锁，资料保持一致。
6. 官方接口拒绝未认证和跨站访问。
7. 窄窗口按插件容器尺寸响应，不横向撑破。

自动化入口：`tests/native-ui.mjs`，只连接已经启动的隔离测试实例。测试身份与口令均为合成数据，日志和备份位于 `.artifacts/`，不提交到仓库。

## Host / Client 实现

- Host：`src/index.ts`，公开 `connection.fetch.register` 的独立 `/api/dsh-friends` 路由，继承官方拥有者认证和来源检查。
- Client：`src/client.tsx`，公开 `sidebar.panellist` 与 `main` 插槽；通过同源、带超时的请求调用上述 Host 接口。
- 存储：`storageDomain` 的独立 `dsh_friends` domain。身份为 NIP-49 密文；聊天/好友/队列作为自加密的 NIP-44 密文持久化。
- 主题：官方 Button 与 `--dsw-*` 变量；插件不改宿主主题或全局元素样式。
- 生命周期：注销入口/路由，停止订阅与定时器，等待存储写入后释放身份和 domain。

rc.5 中尝试单独 `rpc.handle` 通道时遇到作用域注入激活错误。实际实现采用同样公开的 exact Fetch 注册，不修改 SDK，也不占用只能单注册者使用的共享 `/api` 拦截器。

## 实际通信测试

`tests/service.test.ts` + `tests/relay-fixture.ts` 启动真正的回环 WebSocket 中继，两个独立服务实例使用各自密钥与加密存储，完成：

- 默认不发布，确认后互相发现名片与接收配置。
- 好友邀请 → 接受 → 双向关系。
- NIP-59 封装私聊，检查中继与磁盘记录中均没有正文。
- 发布拒绝 → 失败状态 → 重试，不产生重复消息。
- 断线后保留待发，关闭并重建服务，解锁后恢复发送。
- 停止发现、屏蔽、错误口令、存储失败与损坏保护。

密码保护还对照 NIP-49 的公开解密向量，并测试在运行高成本解密前拒绝恶意工作因子。

## 公共中继现状

仅做连接验证：`relay.damus.io`、`relay.primal.net`、`nos.lol` 经 DSH 官方代理策略均握手成功。本次网络直连均失败。

没有向公共中继发布名片、好友邀请或消息。**连接验证不等于其接受本插件协议，更不等于公网交付完成。**

## 尚未通过的发布门槛

- 不同公网下两个真实 DSH 实例的发现、接收与消息恢复。
- 每个候选中继的自定义应用数据写入、私信接收、认证/限流和保存策略。
- 官方 Desktop Electron 窗口中的安装/卸载和完整操作。
- WorkDSH、Windows、macOS Intel 与其他 DSH 版本。
- 完整聊天备份、多设备历史一致性、超容量后的归档与迁移。

在这些门槛完成前，仅提供开发验收产物，不创建正式 Release 或宣传“公网已可用”。

公开发现暂用实验 kind 30388 和独立 d/protocol 命名空间。没有将 NIP-78 的本人私有数据类型当作公开目录；正式发布前仍需确认类型冲突与实际中继接收策略。
