## 本轮实际发现并修复

### 公共消息正常，私聊收不到

实际探测收到 Damus 的 `auth-required: requested filter requires authentication`。原实现把公共和私信过滤器放进同一个订阅，也没有 NIP-42，不能以“发送被接受”推断对方能读。

现实现分离大厅和私信订阅。已解锁且同意连接时，Host 仅针对已选中继的一次性挑战签署 NIP-42；验证后重新订阅私信。验证事件不广播，失败只影响私聊接收，不关闭公共大厅。以真实公网私聊收取及要求认证的回环中继双重验证。

### 更新后界面与 Host 不是同一版

旧底座中“立即启用”可能更新 Client，已经运行的同名 Host 实例仍被复用。现在快照报告实际后台版本，Client 检查并提示不一致。测试通过正常安装/组件启用和完整重启核对最终 Host 已更新，不用改官方代码或绕过安全存储保留明文密钥。

### 身份和收信配置

补齐 `inboxUrls` 的存储字段；解密历史使用经过 schema 处理的结果，兼容新增默认字段。公开发言后单独准备私信接收配置，不因此发布完整兴趣名片。联系人昵称从已验签公开发言保存，避免必须先加入发现才能识别私聊对象。

## 通用插件包新增 Windows 适配 · alpha.8（2026-10-31）

新增 Host 端 Windows PowerShell 5.1 / .NET DPAPI CurrentUser 适配。随机解锁秘密仅通过子进程标准输入传入，标准输出仅供 Host 捕获，不进参数、Client RPC 或日志。加密记录保存在 `%LOCALAPPDATA%\DSHFriends\ProtectedIdentity\<随机 UUID>.dpapi`；DSH 自己的 storageDomain 仍保存加密身份和业务记录。写入后必须读回验证，失败不使用明文回退，不覆盖旧身份。固定脚本不改变 PowerShell 执行策略、不要求管理员权限。受企业策略限制或安全存储失败时拒绝创建身份，仍可浏览历史。

采用微软官方 API：[DataProtectionScope.CurrentUser](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dataprotectionscope?view=windowsdesktop-9.0)。这不是 Mac 身份迁移：Windows 首次发言生成独立身份，昵称可以相同但身份不同。本机自动身份当前无跨设备导出。

本机新增适配器契约测试；真正 DPAPI 读写/重建适配器/磁盘不含明文测试仅在 Windows 执行，Mac 上明确跳过。当前未拥有 Windows 实机验收结果，不能把该包称为 Windows 已验证版。原 macOS Desktop 证据对应 alpha.7 及更早构建，不能称为 alpha.8 Desktop 重跑。

alpha.8 本次交付检查：类型检查、Host/Client 构建通过；本地测试 22 项中 21 项通过，Windows DPAPI 实机用例在 macOS 明确跳过 1 项。打包后单独检查发布内容与版本，不包含测试账号、私钥或本机 profile。


## 通用包 alpha.9 · Windows 系统代理修正（2026-10-31）

用户在启用系统代理的 Windows 上反馈三个公共节点均连接失败。定位到原实现使用 Node 原生 WebSocket，没有读取 Windows 的 WinINET 当前用户静态代理设置；截图不能独立证明该设备的全部网络问题，最终连接恢复仍需 Windows 回测。

现改为 Host 专用 ws 连接，经公开的 nostr-tools AbstractRelay websocketImplementation 接口注入；按环境变量或 Windows 当前用户系统代理选择 HTTP CONNECT / SOCKS 代理，保留证书校验和原有签名验证。只读取 HKCU Internet Settings，不修改系统配置、不读取 DSH 模型密钥。环境 NO_PROXY 与 Windows ProxyOverride 分别处理。仅 PAC 的配置明确报不支持。连接窗口由 4 秒延长到 12 秒。社区设置新增可见的连接路径与脱敏失败原因，原来仅悬浮标题的反馈不再是唯一错误入口。

新增四项检查：Windows 静态代理解析/绕过/PAC 拒绝、HTTPS_PROXY 对安全 WebSocket 的映射及 NO_PROXY、真正经本地 HTTP CONNECT 中继的收发、失败反馈不泄露代理凭据。该代理收发使用不可直连解析的测试域名与仅回环代理，不写入公网。Mac 本机 26 项测试中 25 项通过、Windows DPAPI 实机项仍跳过；类型检查、构建与聊天 UI 检查通过。不得把本机代理模拟称为 Windows 注册表实测或 Windows 连接已恢复。


## alpha.10 · 自建实时中继与公开运营看板（2026-10-31）

按用户最新要求，自建服务不保存聊天内容；仅保留累计用户、日活、公开消息计数与脱敏去重标识。公开名片、收件路由在内存限时缓存，正文和加密信封既不落盘，也不放进供历史查询的缓存。客户端已有记录继续留在本机；离线不补发。此前持久化聊天的设想已撤销，最初空的 SQLite 聊天数据库已核对事件数为 0 后删除，旧服务停止。

服务基于官方维护中的 `fiatjaf.com/nostr/khatru` 公开接口构建（模块版本固定于 go.mod/go.sum），使用其签名验证、订阅匹配和 NIP-42，未自行实现密码算法。仅自有统计适配器持久写入 HMAC 脱敏身份/事件标识与计数，主进程无聊天持久化接口。独立受限服务、域名 TLS、自动续期、运营统计备份均已配置。公开页面无管理写操作。

`.artifacts/selfhosted-relay-acceptance.json` 记录同一 Mac 环境的两名合成身份经真实 TLS 公网服务器完成八项验收：NIP-42、三房间实时互收、引用、邀请/接受/加密私聊、新订阅无历史、离线不重放且本机缓存仍在、公开统计无正文、服务器重启统计保持。写测试使用隔离的运营统计目录，最终正式目录不预填验收人数。Go 隐私/恢复检查及竞争检测通过；govulncheck 未发现调用链可达的漏洞，但仍报告未触达的间接依赖告警，不宣称零漏洞。

通用包切换到自建节点，不自动同步旧中继的聊天数据。已发布过收件路由的身份会重连重发，并定期续发不含正文的路由信息，以适应中继重启后内存路由重建。原生聊天页明确显示实时中继的边界，默认节点不再提供“加载更早的服务端历史”入口。双方需要更新到新包才会共用该节点。


### alpha.10 最终历史口径（用户随后明确选择，覆盖上一节的“纯转发无历史”方案）
