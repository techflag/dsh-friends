# 产品与交互设计 · 公共大厅优先

状态：2026-10-31，根据用户反馈调整产品方向。公共大厅已接入真实 Host/Nostr 通信，并完成原生 WorkDSH 与独立官方 Web 的公网全链路验证。原生桌面、不同版本及不同物理网络的边界分别记录，不能相互替代。真实接入证据见 NATIVE.md。

## 定位

DSH 搭子是安装在官方 DSH 上的社区交流插件。让使用者先围绕具体话题交流，再自然认识彼此。WorkDSH 是兼容宿主，不是依赖；官方 DSH 与 WorkDSH 不按发行版隔离。

核心路径：打开大厅 → 看看大家聊什么 → 跟一句 / 提一个问题 → 围绕话题认识人 → 自愿转到私聊 → 留下联系人。

默认入口要给出值得参与的对话。用户可以只看；第一次参与不需要先筛选陌生人、填写长名片或加好友。昵称、签名身份和备份围绕实际动作逐步引导，不做首屏任务清单。

## 欢迎接待与 AI 助手

用户明确要求“不要冷场”：进入有人欢迎、开口有人回应、运营者知道有人到访。当前实现包括真实进房/在线状态、固定本地欢迎、到访提醒，以及服务端 DeepSeek AI 在新人发言无人回应时接话。真人引用回复会取消待发 AI 回应，机器人不会回应自己；服务端未配置密钥时只关闭 AI 接话，公共聊天不受影响。不能用假聊天制造热闹。详见 [接待说明](RECEPTION.md)。

## 信息架构

DSH 原生侧栏只注册一项“搭子”。插件面板顶部四个标签：**大厅 / 消息 / 联系人 / 我**。

| 位置 | 职责 |
|---|---|
| 大厅（默认） | 公共聊天流、引用回复、公开发言、查看发言者 |
| 消息 | 已同意的私聊与私聊申请 |
| 联系人 | 已建立联系的人；“发现新搭子”是可选的同好名片入口 |
| 我 | 本地身份、昵称/名片、发现可见性、连接与屏蔽 |

保持紧凑顶部导航，不增加内部侧栏、右侧介绍卡片或第三列。原生 AI 对话、模型、轨迹和任务浏览器仍由 DSH 宿主管理。

## 第一次使用

1. 打开看到大厅。未连接时展示清楚的空状态和“进入大厅”，不放虚构热闹或要求先加好友。
2. 首次连接说明公共中继会看到连接信息，经用户同意连接；只读浏览不要求先创建发言身份或公开完整名片。
3. 用户有话想说时，首次引导设置昵称和本地签名身份。口令/备份说明准确；跳过备份不会显示“已备份”。
4. 返回原先的发言草稿和回复对象，用户点击“公开发言”。正文、公开身份标识及昵称可被公共网络保存。
5. 点击发言者看简短名片，想继续时选择“发起私聊”。对方同意后进入私人会话。完整兴趣名片加入发现仍单独自愿。

原型只模拟交互；默认零联系人、零私聊申请，使用明确标注的虚构大厅记录。已有联系人演示场景通过 `?scenario=returning#messages` 访问。正式插件不加载这些演示人物。

## 大厅的交流方式

- 使用大厅、插件交流、随便聊聊三个默认房间；日常接待优先在大厅开展，暂不开放自建房间。私密群组另行评估。
- 鼓励具体话题：正在尝试什么、遇到什么问题、发现什么好方法，也容纳轻松日常交流。
- 每条发言可引用回复，能看懂接的是哪句话。首版引用就地展开，不再加一个讨论侧栏。
- 新消息在读旧内容时只提示，不强制把用户拖到最底部。用户自己发言后进入最新位置。
- 昵称打开名片，私聊入口出现在具体互动之后；不把每条公开消息变成“加好友”按钮。
- 切换标签、选择/取消引用保留草稿。Enter 发送，Shift+Enter 换行；中文输入法组合期间不发送。
- 公共消息按真实中继确认显示发送状态；未连上时保留草稿，提供具体错误与重试。
- 公共聊天为公开文本；私聊使用加密载体。二者在发送区区分，避免误以为大厅也保密。

## 私聊与联系人

“发起私聊”复用已有加密邀请/同意机制，附一句来自当前话题的介绍。陌生人请求单独进入申请区；对方同意后再进入正常会话。联系人关系随双方交流建立，不作为参与大厅的门槛。

| 私聊状态 | 可以说明的事实 |
|---|---|
| 草稿 | 尚未提交，按会话保留 |
| 正在发送 | Host 已持久保存待发内容并尝试发布 |
| 已到中继 | 至少一个收件方指定中继接受加密包，不代表对方已读 |
| 发送失败 | 保留内容，显示可理解原因与重试动作 |
| 暂不可发送 | 对方接收配置、关系确认、屏蔽等前提尚不满足 |

保持邀请和消息 ID 去重，恢复待发队列，历史损坏不能覆盖为空。屏蔽影响本地展示与收取；不承诺删除他人在互联网上保存的内容。

## 人少时与公共秩序

真实大厅无人发言时保持真实在线状态，同时由明确标注身份的接待助手主动欢迎并帮助开口；新人发言无人回应时，由 DeepSeek AI 按节流规则接话。不能把安静空状态当作接待完成。演示数据与真实参与者严格区分。

第一版就需要本地屏蔽、过长内容限制、重复事件去重、发送节流和有界同步。单个公共中继并不提供全网统一治理；举报、管理员和公共治理是后续专项能力。先观察真实使用，再决定是否引入更多房间。
