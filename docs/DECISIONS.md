# 设计决策记录

以下保留各阶段设计决策；当前实现与实测范围以日期较新的决策及 NATIVE.md 为准。

## ADR-001 · 官方 DSH 独立插件

背景：用户希望官方 DSH 用户和 WorkDSH 用户互联。

选择：公开 Host/Client 插件、一个原生侧栏入口和主面板，插件内部导航；与 WorkDSH 企业账号无耦合。

备选：独立桌面应用 / WorkDSH 内置功能 / 修改官方包。前两者偏离通用插件目标，第三者增加版本维护成本，均不采用。

代价：必须实测纯 DSH 的 API、存储和卸载行为；不能利用 WorkDSH 私有便利接口替代缺口。

## ADR-002 · 先验证公共 Nostr 中继

背景：希望无需先购买服务器即可让互联网用户互相认识。

选择：小规模验证公共中继上的自愿发现和加密私聊；可配置节点，不依赖单点。

备选：自建社区服务器更易统一账号、目录与管理，但需运维；纯 P2P 仍需引导节点、NAT 处理与离线消息方案；Tor 解决网络位置隐私，不直接提供社区目录。

代价：节点规则、网络可达性、数据保留不由项目控制。自定义发现协议必须实测；不承诺无成本、永久可用或 IP 匿名。

## ADR-003 · 发现默认关闭，聊天先好友邀请

背景：本机 Agent 工具用户不应在安装插件时自动被公开。

选择：先浏览/填写本地名片，显式同意才公开；请求箱与正常聊天隔离。

备选：安装即上线、更像即时聊天室，但公开预期和骚扰成本更高，不采用。

代价：多一步加入操作；无法承诺删除公共副本。通过明确字段确认和温和引导减少困惑。

## ADR-004 · Host 管身份和网络，Client 管界面

背景：DSH 支持多环境和插件 UI 生命周期，不能让浏览器持有私钥。

选择：签名、加密、队列和存储置于 Host，Client 只通过受限业务命令操作。

备选：前端直接接 Nostr 较快，但密钥、重载和重试难管，不采用。

代价：先验证 Host 安全存储能力；缺口不得以明文 JSON 保存替代。

## ADR-005 · 不添加未经证实的消息回执

背景：中继接受不意味着好友收到或已读。

选择：首版展示已到中继、失败、待核对，暂不显示已读。

备选：仿聊天软件直接显示“已送达”容易误导；完整送达/已读协议扩大首版范围。

代价：用户看到的状态更保守，需要简短解释。

## ADR-006 · 先离线原型再做通信插件

背景：本轮明确要求先设计，且前期有主题、滚动、伪原生界面问题。

选择：以无运行依赖的可交互原型审查四个页面、双色与窄屏，明确所有模拟状态。完成设计后进入真实 Host/Client 接入。

代价：原型 DOM/CSS 不是最终 React 插件代码，接入时需使用官方组件、主题与容器响应式；不直接打包网页冒充正式插件。

## ADR-007 · 加密身份与官方 exact Fetch 接口（Implemented）

身份选择 nostr-tools 的 NIP-49 口令保护，原始私钥不经过 Client，也不降级保存明文。聊天与关系以自加密密文交给官方 domain。代价是每次 Host 重启需要解锁，身份备份不包含完整聊天历史。

Host UI 接口采用公开 Connection exact Fetch 注册，继承官方拥有者认证与来源检查。独立 RPC 通道在 rc.5 实测遇到注入错误，共享 /api 拦截器又只允许一个注册者，因此均不使用。这样无需修改官方代码，也不抢占其他插件的接口。

## ADR-008 · 先公共交流，再建立联系（设计已更新，通信待实施）

用户指出：初次接触时没有理由先加陌生人为好友。默认入口改为单一公共大厅，先阅读与参与具体话题，再自愿查看名片、转私聊。联系人与同好名片列表为后续可选路径。

先集中对话，引用回复承接话题；人少时保持真实空状态，按真实使用再评估房间。阅读不要求先建发言身份，首次发言再引导昵称、密钥保护与公开内容确认。公开大厅为明文，现有加密邀请用于双方同意的私聊。

代价：Host 需要新增公开消息路径、无身份只读连接、公共秩序控制与新的双端验收，不能把旧私聊插件更换标签就宣称完成大厅。

## ADR-009 · 公共/私聊订阅隔离与 NIP-42（已实现）

公网实测中，Damus 拒绝未认证的 1059 读取。公共消息 ACK 不能代表私信接收准备完成。选择独立订阅，在已解锁且同意连接时进行范围受限的 NIP-42 验证，成功后重新订阅；验证失败不关闭大厅。回环和真实公网均验证。

## ADR-010 · 聊天交互与实际后台版本核对（已实现）

用户指出日志式公共列表不友好。使用左右气泡、就近回复、两行引用与紧凑常驻输入区；实际新消息不能抢走正在阅读历史的位置。深浅主题和窄面板在真实 DSH 渲染器验证。

原生底座可能先加载新 Client，却复用旧 Host；增加实际版本字段与界面提示，通过正常重启加载新后台。保留加密身份，不以绕过口令恢复内存密钥换取无感更新。

## ADR-009 · 默认聊天室与无账号操作方向（2026-10-31）

用户决定先只使用默认聊天室（大厅、插件交流、随便聊聊），暂不实现创建频道；功能后续迭代。

本机使用不要求用户注册搭子账号、设置搭子密码、手动保存或填写私钥。此要求针对使用流程，不表示取消 Nostr 事件签名。发言身份应由 Host 自动生成并管理，固定昵称可后续修改，不绑定宿主账号。

实现前置：验证适合的 Host 安全持久存储，保证重开身份稳定。当前代码仍为口令加密身份；本轮仅确认方向，未移除保护、未迁移或覆盖已有身份。已安装 SDK credentials 的默认本地实现是 `.credentials.yaml`，不能将普通凭据文件直接称为系统钥匙串或以其代替已验证的受保护存储。若宿主无合适能力，暂停自动身份持久化，记录缺口；不以每次随机新身份冒充可持续的联系人/私聊体验。

## ADR-010 · 上下布局与本机免口令（2026-10-31）

用户确认整体上下布局：顶部导航、顶部默认聊天室，下方连续聊天，输入区固定底部。取消插件内部左右两层导航；消息仍是别人左、自己右。紫色系固定配色覆盖插件自身的按钮、输入框、状态和引用，不修改宿主主题或文件。

Mac 新用户首次发言由 Host 自动生成身份；随机解锁凭据存入系统登录钥匙串，NIP-49 加密身份与加密私聊继续留在 storageDomain。已用隔离钥匙串记录完成真实写入/读取/删除验证，并在真实 Desktop 完成首次发言和全进程重启验证。凭据通过受限 stdin 输入和捕获输出传递，不放入命令参数、Client、日志或普通 JSON 配置。先验证受保护记录读回，再提交身份元数据；失败不留下可见未持久身份。

旧版锁定身份不会自动被替换；恢复入口置于“我”的高级区域。新身份不要求注册、口令表单或手动备份。新模式暂不提供跨设备备份导出，不能导出用户无法解开的内部备份。其他系统尚无已验证自动保存适配，失败时保留只读历史功能，不降级明文存钥匙。
