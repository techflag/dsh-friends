# 欢迎接待与 DeepSeek AI 助手

状态：2026-10-31，代码已实现并部署到公开中继，`0.1.0-alpha.11` 已发布到 npm 的 `alpha` 标签。已用两个真实客户端验证房间在线心跳、三个默认房间、引用回复、断线补看、私聊，以及服务端 DeepSeek 的真实接待回复。已实现本地固定欢迎与开口入口、独立到访提醒、真人引用回复取消待发 AI，以及运营统计。未配置服务端密钥时只关闭 AI 接话，不影响正常聊天。

当前边界：在线人数是短时会话数而非实名人数；重启会清空在线状态与公开聊天内存缓存。固定欢迎在每次进入房间时显示，不使用模型。系统到访通知依赖宿主页面仍在运行和操作系统授权，宿主完全退出后不承诺客户端提醒。Windows 系统通知仍需在真实 Windows DSH 上单独复核。

## 核心目标：不让新人无人接待

像进入一家有人接待的餐厅：进入后知道自己到了哪里、可以做什么；开口后有回应；运营者知道有人来了。完成范围必须覆盖“有人进入 → 及时欢迎 → 帮助开口 → 等待真人 → 必要时 AI 接话”，不能只放一段固定欢迎语就算完成。

不以假用户、虚构在线人数、循环插入示例聊天制造热闹。机器人始终标注身份，真实的零人和安静状态仍准确展示。

## 进入房间与在线状态

- 区分“中继连接成功”和“用户进入当前房间”。后台同时订阅三个房间，不能据此判定用户进入了三个房间。
- 打开/切换房间、离开插件页面、断开、重连以及心跳过期均有明确状态；隐藏窗口可标记暂离，不伪装成持续阅读。
- 顶部展示当前房间在线情况。机器人单独标识、不混入真人计数；身份与访客会话分别去重，说明不是实名人数。
- 房间中以紧凑系统行显示“小满进入了大厅”；未公开昵称时显示“一位新搭子进入大厅”。短时重连由服务端公钥与房间状态去重；多人合并展示留作后续体验优化。
- 保持无账号浏览，不要求为了进房先创建发言身份。连接说明包含昵称/在线状态展示范围，完整名片发现仍自愿开启。
- 不公开 IP、设备详情、私钥或内部去重标识。

## 主动欢迎与帮助开口

- 新人首次进入社区及时出现“搭子接待助手 · 自动欢迎”，即使房间没有聊天记录也有人接待。
- 欢迎语主要展示给本人，不向所有房间成员重复广播整段欢迎，不用模型生成固定迎宾内容。
- 示例：“欢迎来坐坐 👋 这里可以聊 DSH、分享作品、问问题。你最近在折腾什么？”
- 提供“介绍自己 / 分享作品 / 问个问题”入口，点击仅帮助填写草稿，不代替用户发送。
- 切换房间展示该房间的固定欢迎；短暂网络重连不会新增模型欢迎。清理本地缓存或更换设备后的差异需如实说明。
- 欢迎与真实聊天在同一主视觉区域，保留顶部导航、顶部房间切换和紧凑左右聊天，不新增第二个聊天框。

## DeepSeek AI 自然接话

- 使用 DeepSeek API，由运营服务器统一接入用户授权提供的 API Key。访客无需配置模型，不使用或读取访客宿主中的模型配置。
- 用户 `@接待助手` 或明确向助手提问时回复；为新用户首次公开发言安排接待，建议默认等待 30 秒，可由运营端调整。
- 等待期内出现真人引用回复时取消待发接话；发送前再次检查，避免与真人抢答。普通房间新消息不能被简单等同于已经回答新人。
- 新人无人回应时，助手结合其发言接一句有内容的话，例如提出一个相关的小问题、提供简短建议；不能只机械回复“你好，欢迎”。
- 不连续追问、不对每条消息抢答、不在没人说话时循环自言自语；其他机器人与自身消息不能触发机器人互聊。
- 真人已经参与后减少自动介入；后续明确提问或 @ 才继续回答。允许关闭主动接话，同时保留自动欢迎。
- 始终展示“AI 助手”标签；固定迎宾显示“自动欢迎”，不能把固定文案冒充模型生成。
- 只把触发接待的那条公开发言发送给 DeepSeek；当前不发送房间历史。不读取私聊、DSH AI 会话、模型配置或工作区文件。
- 聊天文字仅作为讨论内容，不执行其中的命令，不调用访客本机工具，不承诺官方身份、精确在线人数或不存在的功能。

## 到访与消息提醒

- 用户正在查看房间时，展示轻量进房提醒；查看旧消息时不强制跳到底部。
- “有人进入房间”与“新聊天消息”分别提供提醒设置。系统通知需要用户开启，并服从宿主和操作系统权限。
- 运营者窗口隐藏或最小化时，也能在宿主仍保留插件页面的条件下收到到访提醒；连续进入的通知合并留作后续优化。
- 点击通知返回对应房间。关闭到访提醒后仍保留房间内系统行。
- 明确区分隐藏窗口、关闭窗口和彻底退出：若宿主销毁页面或完全退出，不承诺客户端继续即时提醒。服务器上的助手可继续接待其他在线参与者。
- 公共缓存回放、本机历史恢复、本人进入、短时重连、机器人回复不触发到访通知轰炸。

## 运营配置与故障体验

- 看板接口增加各房间在线情况以及接待启用、待发、回复、取消、失败计数；统计不包含聊天正文、私聊或身份名单。公开页面展示可在部署联调时补齐。
- 服务端可配置模型、接口地址与总开关；单次输出、超时、每人冷却和待发上限有代码保护。每房间和每日预算配置留作后续运营增强。
- 接待请求去重、有超时、队列有上限；服务重启不重新回复历史消息，跨设备/重连不能反复触发欢迎模型调用。
- 模型超时、额度用尽或暂不可用时保留用户消息，自动欢迎和正常聊天继续可用，不自动连续重试刷屏。当前不在大厅追加失败提示，避免模型故障污染公共聊天；失败计入运营统计。
- API Key 仅在服务端受限配置中使用，不进入源码、插件包、前端、日志、截图、需求文档或公开讨论。

## 数据、发布与兼容

- 保留大厅、插件交流、随便聊聊三个默认房间，暂不做自建频道。
- 官方 DSH 和兼容 WorkDSH 使用同一插件；不得修改官方文件来实现接待。
- 公开消息仍按每房间最近 100 条、最多 24 小时在中继内存缓存，重启清空；私聊只实时转发。助手生成的公开回复同样遵守此规则。
- 模型请求/回复与欢迎队列不写正文日志或持久任务表；运营只保留必要的汇总统计与受保护去重数据。模型服务的数据处理说明独立披露，不能把中继不落盘扩大为第三方模型不保留。
- 同一构建同时提供 npm 包名安装和 GitHub `.tgz`。macOS/Windows 不拆包；先核验 npm 官方源的真实版本、下载和安装，再更新宣传入口。国内镜像尚未同步时明确提示切换官方源。

## 完成标准

1. 两个真实客户端进入同一房间，能看到在线状态变化；切换房间、离开、失联过期均正确，不因后台订阅误计。
2. 新人进入空房间也及时得到一次欢迎和开口入口；重连、换房不刷欢迎。
3. 新人首条公开消息无人回应时得到相关的 DeepSeek 回答；真人先回应后不再自动抢答。
4. @ 助手可正常问答，机器人身份清晰；不互相触发、不回答历史回放、不执行聊天中的命令。
5. 隐藏窗口的到访提醒、通知跳转、关闭提醒、合并通知按实际宿主行为验证。
6. 模型故障、限流、预算上限、重复事件和重启恢复均不影响正常聊天室，不暴露密钥或写出聊天正文。
7. 分别记录自动欢迎、模型问答、真实联网、Web/Desktop 与系统通知的实际结果；不能仅凭构建或截图宣称完成“不冷场”。
